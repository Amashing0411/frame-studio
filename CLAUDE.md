# Frame Studio

A browser film engine: Three.js r128 plays a scenario JSON as a 9:16 portrait film (1080x1920 delivery) with procedural characters, a shot timeline, audio and MP4/WebM export. It will be deployed to Vercel.

## Standing rules (every step)

1. **Screenshots for anything visual.** Use the `workflow-progress-screenshots` skill: send real renders (start, key moment, result) as files as the work progresses, and look at every image before sending it.
2. **End every step with an `audit-verify-explain-grade-5` summary:** what changed, why it matters, how it was verified, what is still not proven.
3. **Never wrap functions. Edit them.** Do not write `const fooV1 = foo; foo = function (...) { fooV1(...) }`, replace a function from a later file, declare it twice, or override a method like `renderer.render`. Change the original definition in place. `tools/check-wrappers.mjs` enforces this and runs before every build (`prebuild`), so a wrapper fails the build.
4. **Commit only after the user says "approved", then push.** Until then, leave changes uncommitted and show them. After each approved commit, push to GitHub (`git push`, remote `origin` = https://github.com/Amashing0411/frame-studio, public).

## Layout

A Vite static site (`npm run build` → `dist/`, deployable to Vercel as is).

- `index.html`: page markup. `<!-- classic-scripts -->` marks where the three scripts are injected.
- `classic.config.js`: **load order** of everything. The app is three classic (non-module) scripts sharing one global scope, exactly like the original single file: `vendor` (npm libraries), `engine`, `studio`. Each is its listed files joined in order. Add new source files here.
- `src/engine/00-15-*.js`: the core engine (renderer, sky/weather, helpers, scenery, vehicles, characters, world build, fx, state, navigation, faces/poses, life, camera, validation, step, samples).
- `src/studio/*.js` and `src/assets/*.js`: the studio layer, numbered in load order across both folders (`assets/` holds asset definitions: archetypes, recipes, mesh factory, character style v3, world revamp).
- `src/styles/studio.css`: the interface design system (Step 11), light and dark tokens on `:root` (`data-theme` from the top-bar switch, saved in localStorage, otherwise the system setting). Motion animates only transform/opacity, under 300 ms, no hover effects on touch, reduced-motion respected. The film canvas is only sized, never styled, so frames and exports are unaffected.
- **Interface (Step 11)**: `index.html` is a top bar, the film stage (film, transport with shot marks on the scrubber, shot cards) and one side panel with four tabs: **Story** (story picker, Check story, on-demand camera/safe-zone check, the JSON script and the workshop planner folded), **Shot** (the shot inspector: camera and movement as picture buttons that mirror the hidden `#shotPreset`/`#shotMove` selects, fine-tune folded, people's actions), **Guide**, **More** (Look, Sound, Asset library, Model studio, Export as folded sections). Every original element id is kept, so the scripts and tests address controls exactly as before; `tabInspector`/`tabLeft` route into these tabs. On phones (≤760 px) the tabs become a bottom bar and the panels a bottom sheet (drag or tap outside to close). `src/studio/20-ui-shell.js`: `initUIShell` (first thing in `initializeWorkshop`), `finishUIShell` (last), `showPanel`, `openMoreSection`, theme, sheet, `castProgress` (the film's loading bar while `loadCast` downloads), `buildChoiceMirror`/`syncChoiceMirrors` (called from `showShotFields`), `foldFieldset`, `renderShotTicks` (called from `renderShotTrack`).
- **Guide tab** (`src/studio/21-guide.js`): rebuilt from the live engine every time it opens (catalog incl. installed/imported packs, people models from the manifest, `PRE`, `MOV`, `EVT`, `CRW`, `EMOS`, `KL`), so new assets, moves, cameras and events appear without editing it. Moves and feelings set the selected character's action in the current shot, cameras/movements/crowd moods set the shot fields, categories open the asset library filtered; script-only names (events, disasters) are copied.
- Validate (`#bv`, "Check story") no longer runs the full-film camera/safe-zone pass; `#checkCameras` does, and so does nothing else (a zone change only redraws guides). Seeks and that pass yield to the browser every ~24 ms with a progress percentage.
- **What if… box** (Story tab, top): `src/studio/22-whatif.js` is the **free writer** (no AI, no server, no cost): `parseWhatIf` reads a sentence for a disaster (quake, zombie, flood, tsunami, else a city story), place, time, weather and "short"; `writeWhatIf` builds the shots from `WHATIF_BEATS` (several wordings per beat, chosen by a seed from the sentence; "Another version" bumps the seed; no three equal shot lengths in a row) through the engine's `mkS`, so the result is a normal schema-7 script. `src/studio/23-ai-writer.js` is the optional **own-key AI writer**: each visitor pastes their own Anthropic API key (memory only, or localStorage `frame-studio-ai-key` when "Remember" is ticked), the browser calls Anthropic directly through the official SDK (`@anthropic-ai/sdk`, lazy chunk via the ES module `src/ai/claude-sdk.js` → `window.loadAnthropicSDK`, never preloaded), default model `claude-opus-5-5` with a picker (Sonnet 5.5, Haiku 5.5), structured JSON output whose enums come from the live vocabulary (`aiSchema`), `effort: medium`, refusal fallback `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`, not for Haiku), typed SDK errors; `aiToScenario` clamps and filters the answer and builds the script with `mkS`. The site itself never holds a key and has no AI bill. "Paste a script from Claude" loads a JSON script from the clipboard (the whatif-director skill's output).

## Reference frames

The frame tool (`--safe off|youtube|tiktok|both` to force a zone) loads each story fresh (ignoring autosave), in the order market, earthquake, outbreak, coast, seeks with the app's own `seekFilm` (fixed 60 steps/s from 0:00) and saves the canvas pixels at 540x960. Repeated runs on this machine produce byte-identical PNGs almost always; since the film target became multisampled (Step 7 revision), a couple of edge pixels occasionally resolve one level apart, so `--compare` accepts a frame whose hash differs when at most 20 pixels differ by at most 2 levels (`NEAR`). Hashes are GPU-specific (recorded on an RTX 4060, Direct3D11); compare on the same machine.

Steps that promise "no visual change" must reproduce the hashes in `reference/frames/manifest.json`.

Three.js sorts opaque objects by material id, so changing which objects share a material shifts a few edge pixels where surfaces touch even when nothing else changed. To prove such a change is otherwise identical, compare with a fixed draw order (`renderer.setOpaqueSort` by renderOrder, depth, object id) before and after.

## People in motion

- `renderCurrent` redraws with `step(0,T)`. `updPerson` keeps the last real speed on a zero-time step (`p.lastSpeed`, reset in `resetWorld`); before, every walker and runner was re-posed `idle` right before each drawn frame, so fleeing crowds slid along standing up.
- A risen zombie's `fall` rests at .05, so the cast body plays `fall` only above .08 (it used to freeze zombies on the first frame of the fall clip).

## Export audio

- Frame-by-frame export mixes the soundtrack offline (`renderOfflineEffects` + `offlineSound` in `src/studio/05-capture.js`): every cue fades in/out (0.25 s; 1.2 s into the end card) instead of switching, the background dips to 45% while a character talks, and the finished mix gets one gain (about -23 dB RMS, peaks under -1 dBFS, scaled by the volume slider).
- Never call `flush()` on the encoders mid-export: the Opus encoder pads its open packet with silence on every flush, which made WebM audio about 2.3% longer than the video (≈1 s late by the end of a 44 s film). The loops wait for `encodeQueueSize` to drain instead; flush only at the end. Verified: MP4 and WebM audio decode to the film's length with 0 ms offset.

## Camera smoothness and performance (Step 13, first part)

- Camera stutter in the premade stories came from the smart camera snapping (market shots 4 and 8, earthquake shot 3: up to 1.4 m in one step) and from full-strength quake shake on close-ups. Fixed by easing the correction (`cameraEase` in `referencedCamera`), moving a camera inside a solid along its line of sight (`avoidCamera`), scaling shake by subject distance, and continuous playback time (`frame()` → `advanceTo(T+wall*speed)`). `node tools/camera-probe.mjs [url]` reports uneven camera steps per story (0 in every story now, apart from the earthquake's intended shake).
- People: `castMergeModel` merges each model's pieces once at load (3-5 draw calls per person instead of 6-18; visible skinned meshes in the earthquake 646 → 210, frames 12-14 ms → 8-12.5 ms on the RTX 4060). `node tools/perf-probe.mjs [url]` measures draw calls, the shadow pass and GPU-synced frame time.
- Preview quality: phones start at 360 x 640 once (`phonePreviewDefault`, localStorage `frame-studio-phone-quality`); `adaptPreviewQuality` lowers the preview when playback drops under ~25 fps. Exports are never affected.
- Not done yet: fitting the sun's shadow area to the camera (the market draws ~1,300 shadow calls; a visual change, planned with the world migration).

## PSX finish and the itch.io packs

- **PSX look (overhaul Phase 2, 2026-10-22)**: `cinema.material: "psx"` turns on the full port of fcidade's CC0 PSX Godot shader (`src/studio/25-psx-shader.js`). `PSX_PARAMS` is the one table of the 34 settings (default, range, group, the shader's plain help, scope): film and screen settings go in `cinema.psx` (film) or a shot's `cinema.psx` (merged on top), model settings in `assets[].psx` (one placed model gets private material copies, `psxApplyAssetLook`). Validated by `validatePsxLook`; exported by `tools/extract-vocabulary.mjs`. The material is injected in place (`psxInjectShader`, no material swaps): snapping and jitter on the film clock, affine warping with `affine_limit`, nearest or N64 3-point filtering, Gouraud light from three's Lambert vertex chunk (`shadows` keeps the film's shadow mask, 0 = PS1), vertex fog, colour bits + 4×4 dither, matcap, emission, billboard, cutout. Per-material settings live in the `PSX_MAT` WeakMap (never userData: `material.clone()` JSON-copies it). The screen effect is the PSX branch of the film post pass (`PSX_SCREEN_GLSL`, on a graded cell-centre sample); PSX now renders at full size (the old 360-wide target is gone). pixel_size is measured on a 1080-wide frame, so a 540 preview and a 1080 export match (`tools/check-psx-film.mjs`: mean difference ~5 levels; every look repeats on a re-seek). A PSX model whose file arrives late gets its own look and the finish in `psxAttach` (`applyCinemaMaterials(preset, root)`). Film fonts: PSX → Microtale (unchanged).
- **PSX look editor** (More › Look › "Open the PSX look editor", `src/studio/26-psx-editor.js`): the itch.io shader viewer inside the studio. ## Known issues

- `updateFloodCamera` lifts the camera after the frame is drawn, and the next `step()` places the camera again with `shotCam`, so the lift may not show during live playback (seek redraws hide it). Check when working on hazards.
- Textures: since Step 7 the people's bone textures are released when a story is rebuilt (texture count 67 / 70 / 70 / 8 across market, earthquake, outbreak, coast, was 235 growing to 778). Check the rest of the texture lifecycle in the performance step.
- The people assets are 14 MB on disk (134 models + `anim-x.glb`), loaded on demand: a story fetches only the people it uses. The crowd and extras are posed only when on screen (`castDeferred` / `syncCastBodies`). Each PSX person has its own texture, so texture counts went up (154 / 208 / 209 / 122 across market, earthquake, outbreak, coast); still within the budgets.
- Foot slide: in the earthquake, panic runners slide about 95% of their distance with both the old and the new cast: a shot boundary switches them from panic to flee, and the shots are wide. Not fixed in Phase 1.
- Fixed in Phase 1: the coast 0:07.5 frame sometimes showed the cabin darker. GLTFLoader creates a model's materials as their textures finish decoding, so material ids came in a random order, and three.js draws same-shader objects by material id: the cabin's overlapping parts (shared vertices) drew in a different order per load. `psxStableMaterials` (24-psx.js) re-creates each PSX model's materials in name order at load (5/5 probe runs identical, was 2 dark out of 4). The people (`castLoadModel`) do not do this yet; each has one or two materials and showed no flake.
- The toon finish posterizes colors, so a few pixels on band edges can differ between runs; compare toon frames with a small tolerance.
- Fixed in Step 2: the outbreak was not repeatable because clouds, stars and rain were placed with unseeded `Math.random`; they now use their own seeded stream (`SKY`).
